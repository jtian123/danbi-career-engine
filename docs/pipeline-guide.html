02 / JOB DISCOVERY

A lead earns its place
on the shortlist.

The engine asks two questions: is this a real, suitable opportunity—and would the daily work help her test a promising career direction?

01 / DEFINE

Start from the profile

Student status, interests still to explore, actual skills, availability and job-specific eligibility. Keep unknown facts visible.

02 / FIND

Gather candidate roles

Scan public boards and run assisted platform/campus searches. Save source, requisition, location and discovery time.

03 / REVIEW

Read the employer JD

Check application availability, degree rules, graduation window, hours, location, technical demands, pay units and deadlines.

04 / PRIORITIZE

Produce today's list

Deduplicate, apply eligibility and freshness checks, rank reviewed roles, and preserve space for exploration.

Commerce & growth analyticsConsumer insightsProduct workBusiness operationsDemand & pricingCommercial financeBI & data analysis

Checks come before scores.

  • Non-US, incompatible degree requirements and engineering-heavy roles are excluded.
  • Unknown graduation, GPA, citizenship or workload requirements remain questions to resolve.
  • A posting must have recent, explicit review and a live employer application route to reach the priority list.
  • Verification older than seven days requires a refresh. Passed deadlines and closed roles leave the list.
  • Maximum two roles per employer; one exploration slot when a qualifying option exists.

An HTTP 200 response, a platform recommendation or an attractive salary is not evidence of eligibility.

How the order is decided

Reviewers assign the components; the engine adds them within these published limits.

Learning & ownership25
Current readiness20
Published pay10

Timing5
Base maximum100 points

An ordering aid, not an interview probability. Unknown conversion prospects earn no bonus.

Feedback changes the next search. “Interested,” “curious,” and “not for me” influence career preferences in small, bounded steps. Disliking a role's pay or timing does not imply disliking its career direction. Applied roles leave the daily shortlist, while their history stays recorded.

What happens inside the automatic scanner?

Greenhouse, Lever, Ashby and Workday adapters are implemented. The five configured boards currently use Greenhouse and Workday. Workday searches “intern,” caps each board scan at 200 inventory results and reports truncation; it returns titles that still need a full JD review. Every collected result begins unreviewed. An access block is reported without bypassing it.

Is feedback training a reinforcement-learning model?

No. It is a transparent preference adjustment: 10 × the sum of lane votes ÷ (3 + the number of votes), bounded within ±10 points. A first interested vote contributes +2.5. Votes can change ordering, but cannot manufacture skills, eligibility or a verification result. Feedback exports are validated and repeat imports are idempotent.

03 / RESUME BUILDING

Make the relevant
evidence easy to see.

The job description changes the emphasis. It does not change the facts. Graduate education stays near the top, and practical experience supplies the substance.

01 / UNDERSTAND

Read the complete JD

Identify what the intern will do, what is required and what is merely preferred. Keep eligibility separate from resume wording.

02 / SELECT

Choose supported material

Select relevant claim variants, honest skill levels and two or three courses. Weight the strongest experience.

03 / AUDIT

Challenge the draft

Check every claim against evidence, remove repetition and record genuine gaps. Revise without inventing outcomes.

04 / VERIFY

Render, inspect, release

Create Word/PDF drafts, measure the actual page, inspect the image and recheck the final content before release.

Experience selection

Give the strongest story room.

Usually two or three experiences. Apateu is the main startup anchor; XResearch is optional supporting evidence and receives at most two bullets. Preserve distinct responsibilities and deliverables.

Projects and prior work enter a private evidence bank before they can be selected. New phrasing must preserve source support, ownership and the difference between a plan and an achieved outcome.

Graduate student positioning

Education explains the transition.

Keep USC near the top with a compact course selection aligned to the role. Product roles and analytical roles can receive different educational emphasis.

A course title does not establish a skill, a completed project or mastery. Personal coursework status comes from a confirmed course record.

Automation and judgment have different jobs. The current assistant handles writing and the editorial audit. The code compiles approved material, checks constraints, renders and enforces release requirements. It does not call an independent external reviewer model.

04 / THE WORKING RHYTHM

A repeatable cycle
with useful feedback.

The first shortlist tests assumptions about the work she wants. Each later cycle uses her reactions and actual application progress.

SEARCH & REVIEW

Broaden the opportunity set

Search LinkedIn and Handshake, scan employer boards and check campus events. Include new employers and underexplored directions. Review promising JDs before ranking.

COMPARE & PREPARE

Pick a manageable set

Discuss the daily work, interest, technical readiness and logistics. Build a tailored resume for the selected opportunities. The student reviews and submits applications.

RECORD & LEARN

Bring the feedback back

Record interest and application status in the local dashboard. Export feedback for the next search. Recheck aging postings and update facts only when there is new evidence.

Search→Employer review→Shortlist→Tailored resume→Student decision↺Feedback

There is no unattended schedule, automatic application submission or messaging. The HTML dashboard stores feedback in the browser; exporting creates a portable file. It does not rewrite the original HTML.

05 / THE PUBLIC PROJECT

Readable, inspectable
and easy to keep local.

The public repository contains the engine, this guide, tests and synthetic examples. Personal records and private evidence stay in the local working project.

What is automated today?

  • Configured public ATS scans and research-query generation.
  • Deduplication, eligibility/freshness checks, ranking and feedback imports.
  • Standalone dashboard generation.
  • Supported-claim compilation, Word/PDF rendering and resume release checks.

What needs a person or assistant?

  • LinkedIn, signed-in Handshake and campus searches.
  • Full employer JD review and evidence-backed scoring.
  • Resume writing, source interpretation and editorial judgment.
  • Visual inspection, interview preparation and applying.

Try the public example

Python 3.8+ runs discovery, ranking and draft-plan checks. The repository README explains the document runtime needed for Word/PDF rendering.

What does the public version leave out?

Original resumes, contact details, immigration records, application feedback, private startup extracts, school materials, complete saved employer job descriptions and generated personal resume packets. Its sample records are explicitly synthetic; they are examples for running and testing the system, not applicant facts or live opportunities.

Does opening the dashboard refresh the market?

No. A dashboard is a dated snapshot. Its freshness checks can hide stale roles, but new availability and requirements need a new research/review cycle. Building HTML again is not the same as re-verifying a posting.

What should improve next?

Expand reviewed employer coverage, establish a repeatable signed-in Handshake and LinkedIn research routine, incorporate the student's actual course record, and use feedback to refine career direction. These are workflow extensions; they are not already-connected services.
